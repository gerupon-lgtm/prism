### 短い紹介文（作品カード用）

星の光をプリズムでつなぎ、祭壇の鐘へ導くブラウザゲームです。道やプリズムにかかる時間を読み、分岐や合流を組み合わせながら、課題を満たす経路を探します。その試行錯誤を、通信ネットワークの経路設計への気づきにもつなげることを目指しています。

### 技術欄（作品カード用）

HTML / CSS / JavaScript / SVG / Web Audio API / FM音源 / ダイクストラ法 / PWA / localStorage / Cloudflare Pages

## 2. 詳しい紹介文（既存LPのrecord欄）

以下は掲載原稿案。JSONの `record` にも同じ内容を収録している。

### q：きっかけ

経路は、見た目の近さや通る点の数だけでは決まらない。道を進む時間に、中継点での処理や順番待ちが加わると、どの経路が速いのか。ダイクストラ法による最短経路の計算を出発点に、分岐・合流や、一部の道が使えない場合もつないで動かし、結果を比べられる遊びにしたかった。その試行錯誤を、通信ネットワークの経路設計への気づきにもつなげたいと考えた。

### m：作ったもの

星の光をプリズムから祭壇の鐘へ導くゲームにした。舞台は夜空に浮かぶ遺跡とドーム型の天文台。道をドラッグしてつなぎ、「鐘を鳴らす」で光の動きを確かめる。お試し6問と実践6問があり、速く届けるだけでなく、複数の鐘へ届ける、指定した間隔で鳴らす、道やプリズムが使えない場合にも届くようにする課題を用意した。自由作成では配置や時間を変え、自分の回路も試せる。

### w：難しかったこと

分岐した光が合流すると、中継点で順番待ちが起きる。到着や処理終了が同時のときの扱いも含め、結果を追える計算と記録が必要だった。スマホでは指でパーツが隠れ、秒数や案内が盤面を覆ってしまうこともあった。計算の正しさに加え、何が起きたかが見えて、つなぎ直しやすい画面に整える必要があった。

### a：工夫と現在地

経路計算、画面表示、音を分け、到達時間と記録を保ったまま演出や操作を調整した。音はブラウザ内で合成している。LPにも掲載している「FMオペラボ」から2オペレーターFM音源を流用し、鐘やエレピ系の音色を調整した。ファンファーレにはブラスとStringsを重ねた。実践課題は検査済みの秒数条件から抽選し、満点になる配線を1通りに絞りながら、別の配線でも部分点でクリアできるようにした。

MVPを独自ドメインで公開した。PCでは広い盤面と右側の操作欄を使い、スマホではよく使う操作を下へまとめている。チュートリアルも盤面を隠さない配置へ直した。成績と自由作成の回路は使ったブラウザに保存し、必要な資材の準備後は通信なしでも遊べる。

## 3. 遊びの概要

1. 課題の条件と、道・プリズムにかかる秒数を読む。
2. 星からプリズムや鐘へドラッグして道をつなぐ。途中で分岐する構成も作れる。
3. 「鐘を鳴らす」を押し、光の動きと鐘への到着を確かめる。
4. 到達時間・スコア・出来事の記録を見て、配線を組み替える。

| 要素 | 現在の内容 |
|---|---|
| モード | チュートリアル／連続プレイ／選択プレイ／自由作成 |
| 課題 | お試し6問＋実践6問、計12課題。速さ、本数、故障への備え、複数の鐘、指定間隔、合流待ちを扱う |
| 背景 | 夜空の浮遊遺跡とドーム型天文台の2系統。12種類の背景があるという意味ではない |
| 試行錯誤 | 正解で使わない候補も残し、予想・実行・比較・つなぎ直しで経路を探す |
| 出題の変化 | 実践課題は検査済み条件から抽選。選び直しで切替、「もう一度」と配線クリアでは同じ条件を保持 |
| 満点と部分点 | 実践の各出題は満点配線1通り、別配線での部分点クリアも残す。この条件を全てのお試し課題へ広げて説明しない |
| 光と音 | プリズムの光片、祭壇の鐘、創作の「鐘の星座」、満点時の花火とファンファーレ |
| 自由作成と保存 | 配置・道・時間・光の進み方を編集。回路は10枠保存、JSONファイルの書出し・読込み、実行結果の書出しができる |

光と音は到着した出来事を伝えるためのもの。自由に旋律を作る音楽制作アプリや、音楽に合わせて入力するリズムゲームという説明にはしない。

### 通信ネットワークの経路設計への気づき

遊びながら、道の所要時間、中継点での処理や順番待ち、分岐・合流、一部が使えないときの別経路を比べる。通信ネットワークの経路設計を考える入り口にすることも、この作品のねらい。

| ゲームで試すこと | 経路設計へつながる問い |
|---|---|
| 道とプリズムの秒数を比べる | どの経路を通すと、早く届けられるか |
| 途中で分岐し、複数の鐘へ届ける | 限られた接続で、複数の届け先をどう結ぶか |
| 光が合流し、プリズムで順番を待つ | 合流先の待ち時間が、全体の到着にどう影響するか |
| 道やプリズムが使えない状態を試す | 一部が使えなくても、別の経路で届けられるか |

### 技術紹介の短文案

画面はJavaScriptとSVGで構成し、最短経路の選択にはダイクストラ法、光の分岐や合流後の順番待ちには時刻順のシミュレーションを使っています。鐘やジングルはWeb Audio APIで合成し、鐘には「FMオペラボ」から流用した2オペレーターFM音源を採用。成績や回路をブラウザに保存し、資材の準備後はオフラインでも遊べるPWAとして公開しています。

### 技術説明の区別

- 最短経路の選択と、分岐・合流・待ち列のシミュレーションは別の処理。「全てをダイクストラ法だけで計算する」とは書かない。
- 音は録音済みWAVを鳴らす方式ではなく、公開アプリ内で合成する。全音色が2オペレーターFMという意味でもない。
- Node.jsは開発・検査・ビルド用。プレイのためのNode.jsサーバーや外部データベースを稼働させる構成ではない。
- 抽選するのは検査済みの出題条件。「無限に問題を自動生成する」「全課題が毎回変わる」という仕様ではない。

採用ロゴはPRISM／NOTESの二段、Montserrat 600/500、金色。比率・字間・書体を保つ。独立したロゴが必要な場合は[採用ロゴ資料](../../画面案/ロゴ/README.md)と[現行画面のSVG](../../index.html)を使う。書体ファイルを同梱する場合は[OFL.txt](../../画面案/ロゴ/fonts/OFL.txt)も扱う。

アプリの基調色は濃紺 `#090d1a`、金 `#d6b56a`、明るい文字 `#e3e8f6`。カード周囲は掲載先のデザインに合わせ、画像内のロゴや世界観を保つ。細かな秒数を見せる場合は、縦画像の全体を開いて見られるようにする。

星・プリズム・鐘・背景・案内役は、画像生成ツールで作成・選定した画像を使用。出所と採用範囲は[表示資材の出所](../assets.md)に記録している。星座・花火・光などの動きはSVGで描画する。制作表記は指定どおり **© SIKUMI LAB** とする。

## 6. 遊ぶ前の補足

| 項目 | 説明 |
|---|---|
| 起動 | 公開URLをブラウザで開いて遊ぶ。アカウント登録は不要 |
| 音 | 最初の操作から音声を準備。「音あり／音なし」で切り替えられる |
| 保存 | 成績と自由回路は利用したブラウザに保存。別端末との自動同期はない |
| 通信なし利用 | 初回に通信して資材の準備が完了していることが条件。初回アクセス・更新確認には通信が必要 |
| 更新 | 起動時に新版を確認し、準備できた場合に「更新」を表示。未保存の作業等の保護を確認して適用する |

ブラウザの保存データ削除などで成績・回路は失われる場合がある。新URLと従来のGitHub Pagesでは保存場所が別で、自動移行は行わない。LPの「遊ぶ」は独自ドメインへそろえる。
