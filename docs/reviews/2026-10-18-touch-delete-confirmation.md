# 指がずれた時も削除確認を受け付ける

2026-10-18 / 0.56.0。ローカル検証済み、公開確認待ち。

## 報告と再現

発案者から、Q7で配線を長押しし、OKを押すと見た目は反応するのに削除されず、音も鳴っていなかったとの報告があった。

旧0.55.0をPCのChromeでスマホ相当にし、実際のタッチ入力を送った。Q7の星→A→B→Dを結線してBDを長押しする。OKの中央に触れ、ボタン内のままX/Yを各16pxずらして離すと、押下表示の後に `pointercancel` が届き、クリックが来ず、削除確認が残った。各24pxでも同じだった。ボタン内でのずれ0〜10pxでは削除できた。

削除と操作音はクリック後に動くため、クリックが来ないと押下表示だけになる。スクロールへの切替を止めるCSSだけの比較では、取消入力は止まったが、16〜24pxの移動でクリックが来ない状態が残った。実機の元の操作そのものは未確認だが、報告に一致する表示・削除・音の欠落をPC上で再現した。

## 修正

削除確認のOK・取消だけを対象に、ブラウザのスクロール操作へ切り替わらない指定と、指を離す時の判定を併用する。

- 確認を表示した後、新しくボタンを押し、その同じボタンの内側で指を離した場合だけ既存のクリック処理を1回呼ぶ。移動距離の上限を設けて、ボタン内の有効な押下を捨てる扱いはしない。
- 元の配線の長押しから指を離すだけでは削除しない。ボタン外、取消入力、2本指、回転・非表示・焦点喪失、確認対象の変更、無効なボタンでは確定しない。確認時の回路と選んだ1本の保護を保持する。
- マウスとキーボードは既存のクリック処理を使う。音も同じ処理で1回だけ要求し、音ありなら音源を作り、消音なら作らない。信頼できる指離しの中で必要な音声準備を行う。
- 指離し後にブラウザが余分なクリックを送った場合は1回だけ抑える。新しい押下で直ちに解除し、キーボード由来のクリックは妨げない。700msは重複クリックに対する上限であり、次のタップを待たせる時間ではない。

WebKitでは余分なクリックが別のマウス識別子で、確認の背後にある「鐘を鳴らす」へ届く差も再現した。識別子だけの判定では音が2回になったため、直後の余分なクリック自体を抑える。削除後に勝手に実行へ入らないことも点検する。

指の情報は取消・閉じる時に片付ける。元の長押しが取消入力や2本指で中断された後も、次のOKを妨げない。計算・採点・鐘や各音色・全記録・保存・元座標・方向保持・0.55.0の連続結線と拡大補助は変更しない。表示版と資材版を0.56.0へ更新する。

## 検証

`tests/touch-confirm.test.js` と `設計検証/check_delete_button.cjs` で、新しい押下、指のずれ、削除対象1本、操作音の回数、音源生成・消音、ボタン外・取消・2本指、元の長押しの解放、再操作、余分なクリック、背後への実行防止、キーボード・マウスを確認する。Chromium系は実タッチ・ペンの入力、WebKitは実タッチのタップと合成したずれを区別する。

既存の `check_wire_touch.cjs` は長押し・取消・OK・外側タップ・回転・設定と時間入力・全記録保持を、`check_wiring_help.cjs` は0.55.0の途中保持・結線補助と保存保護を確認する。全単体テストは並列度1、最大5ファイルずつ実行する。

従来の長押し検証器では、文字拡大や回転の直後に配線位置を測っていた。共通の `wiringBounds` で表示位置が安定するまで待ってから測定するよう整え、表示途中の座標で長押ししない。判定の待ち時間や合格条件を緩める変更は加えない。

結果は `設計検証/削除ボタン/0.56.0/`。旧版とCSSだけの比較の不合格は、修正対象を再現した証拠であり最終版の不合格と分ける。スマホ・iPad・macOS Safariの実機操作感・実音は未確認。PC上の音源生成をスピーカーでの聴感の合格に広げない。

## ローカル結果

- 削除と音：4PCブラウザで57項目合格。Chromium系はずれ0・6・16・24pxで選んだ1本を削除し、音源を1回生成。消音・ペンと再操作も確認。
- 既存の長押し・削除・設定・記録保持：4PCブラウザで105項目合格。
- 連続結線・補助と保存保護：Chromium／WebKitで52項目合格。
- 全20テストファイル・161項目、構文63ファイル、52資材の生成が合格。

WebKitのずれ入力は合成入力であり、実指の操作や実際の音の聴取へ合格を広げない。通常タップはWebKitの実タッチ入力を使う。
