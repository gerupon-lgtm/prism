# ファンファーレとプリズム到着の再候補

試聴版2026.10.17-2。F4～F6とR4～R6は未選定で、本体へは未反映。

発案者から、前のファンファーレは楽しそうでなく、プリズム到着は他の候補と音程が重なるとの指摘。続けてブラスとStringsを混ぜる指定があったため、次の3案ずつを作った。

| 種類 | 最初の案（おすすめ） | 2案目 | 3案目 |
|---|---|---|---|
| 100点 | F4 はずむ祝福 | F5 星たちのパレード | F6 小さな凱旋 |
| プリズム到着 | R4 低めの結晶 | R5 中音のピコン | R6 跳ねる到着 |

F4～F6はすべてブラスとStringsを混ぜ、短く弾む旋律と和音、掛け合いを使う。最初に採用済みの鐘を鳴らし、その0.7秒後から始める。2.7秒の操作復帰までに全音が終わる。`perfect-comparison.wav` はF4→F5→F6の順。

R4はE4、R5はB4、R6はF♯4→F♯5。採用済みT2（A5）とW2（A5→C♯6）の音の高さを避けた。`relay-comparison.wav` はR4→R5→R6の順で、各案2回ずつ。ゲームでは到着1回につき1回の合図にする。

ZIPは展開して `index.html` を開くと個別に試聴できる。比較ページの「鐘のあと／単独」でジングルの聴き方を切り替えられる。操作・結線など選定済みの4音は、初回試聴版から本体0.40.0へ別途反映する。

生成は初回と同じサエズリズムの合成コードを使う。原本・初回の音源・採用済みの鐘を変更しない。試聴データは `catalog.js`、合成の呼び出しは `render.js`、再生成はリポジトリのルートで次を実行する。

```
node 設計検証/build_audio_candidates.cjs --folder 音の候補-20261017-2 --playwright-path ＜既存Playwrightのパス＞
```

検査結果は `verification.json`。PCの音声信号・比較ページの検査であり、音楽的な好みやスマホ実機の聴感の採用は未確認。
