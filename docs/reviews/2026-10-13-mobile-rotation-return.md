# 0.11.0：回転後の縮小と横向き判定の修正

2026-10-13。基点ca9af1a、発案者の3画像を根拠に修正。0.11.0を公開し、配信コミット66be1ebca25449ff630d73ad5c86c4b03567fa05と公開資材・操作を照合した。

## 観測と原因の区別

- 実機の画像は全て0.10.0。最初の縦は正しく、横では操作欄が上下逆・盤面が潰れ、縦へ戻すと全体が縮む。端末名・OS・ブラウザ版は未回答。見た目から推定して合格や端末情報へ変換しない。
- 従来の方向保持検証はhasTouchだけを指定し、isMobileを指定していなかった。PCでの合格は維持するが、スマホで起こるページ全体の自動縮小を捉える条件が欠けていた。
- 新検証器でisMobile=true、向き変更の通知→表示領域変更→縦へ復帰を実行すると、元の412×804からinnerWidth=915、表示倍率0.450273へ縮むことを再現した。`portrait return retains page scale`が修正前に不合格。
- 回転途中の横サイズで文書が広がるとブラウザが全体を縮め、縮めた後の大きいCSS座標の幅をレイアウトへ戻すため、その状態が残る。表示領域の幅・高さに表示倍率を掛け、画面上の実寸を使う修正後、両PCエンジンで倍率1・412×804へ復帰した。
- 別途、記憶した縦基準と横方向情報の組合せによって、横の配置が0度または180度となる計算経路をテストで不合格にした。横は90度の配置だけを使うよう整合確認を追加した。実機の横不具合がこの経路で起きたという原因確定はしていない。
