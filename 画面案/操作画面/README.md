# プリズム・ノーツ 操作画面案

版：v0.1.0 / 2026-10-12。**確認待ちの画面案**。ゲーム本体や公開版ではない。

[画面案を開く](index.html)。ネットから書体等を取得せず、同じリポジトリの採用ロゴ用Montserratを使う。HTMLを直接開くこともできるが、ブラウザ検証は一時的なローカル配信で実施した。

## 今回の前提と修正

設定の表示面積を固定で確保すると、頻繁に使う結線の場所が狭くなる。発案者の「設定が大きくて、メイン画面が小さ過ぎる」「設定より結線などの操作が頻繁」と「設定値はプレイ画面に控え目に表示」を優先した。

- 通常は実験エリアを広く使い、設定欄を開きっぱなしにしない。
- 道の移動時間とプリズムの処理時間を、図の近くに小さく表示する。
- 一回の選択では設定を開かず、ダブルタップで設定を開く既合意を維持する。
- 発案者のポップアップ提案を画面案にした。設定を重ねて表示し、背景の実験エリアを縮めない。
- 設定から記録は一回で切替。記録と保存は必要なときだけ共用欄へ表示し、閉じれば通常の広さに戻る。
- 時間の手入力中だけは、既合意どおり実験エリアを隠す専用表示とする。

**結線を主役にすることと設定値の控えめな表示は発案者の指示。ポップアップの採用・寸法・外見はまだ確認待ち。** SD-047の設定・記録の共用欄から、設定だけを浮かせる変更案である。旧合意を黙って書き換えず、[画面配置案](../../基本設計_画面配置案_音の庭.md)と[相談記録](../../基本設計_相談記録_音の庭.md)へ差分を残す。

## 表現の仮置き

| 項目 | 値と役割 | 状態 |
|---|---|---|
| 背景 | 夜空 `#060b14` | 採用ロゴの背景を継承。アプリ全体の採用は確認待ち |
| 主操作 | 金 `#dfb96e` | 採用ロゴのPRISMの色を継承 |
| 設定・記録の面 | `#0d1723` | 仮置き |
| 図と数字 | `#badce9` | 仮置き |
| 文字・補助文字 | `#e2e8ee` / `#a8b9c5` | 仮置き |
| ロゴ書体 | Montserrat 600/500。同梱ファイル。元の96:36の文字比率を維持 | 採用ロゴを小さく表示 |
| 日本語書体 | Yu Gothic UI、Hiragino Sans、Meiryo、sans-serifの順 | 配置確認用の仮置き。書体比較は外見の相談で行う |
| プリズム・遺跡・祭壇 | SVGの図形 | 配置確認用。造形の採用ではない |

配置は結線を主役に、名称・値を図の近くへ置き、操作欄は必要時にだけ開く。ロゴ以外の装飾を足して表示領域を圧迫しない。常時動く装飾は用意しない。

## 表示する状態

URLに `?view=...` を付けると各状態を直接見られる。

| 状態 | 表示内容 |
|---|---|
| `play`（初期表示） | 広い実験エリア、控えめな設定値、実行操作、設定・記録・保存の入口 |
| `settings` | 設定ポップアップ、対象名、時間／使用状態の切替、増減・手入力、削除・閉じる |
| `records` / `record-detail` | 見本の40件と詳細6項目を、広さに応じたページで表示 |
| `saves` | 見本の10枠、読み込み・名前変更・対象名付きの削除確認 |
| `input` | 時間入力、全選択、誤入力理由、確定・取消 |
| `guide` | 別見本で練習する案内と、元へ戻る入口 |
| `save-error` | 名前を保つ表示、再試行、回路ファイルへの書き出しの入口 |
| `score-error` | 今回の点数と保存済み最高点を分け、未保存・再試行・続けるを表示 |
| `delete` / `load-protect` | 削除対象と接続する道、読み込み前の保存して入替／保存せず入替／取消 |

`&long=1` は長い保存名、`&empty=1` は記録・保存が0件の見本。表示値・成績・40件の記録・10枠はすべて合成した見本で、利用者のデータや実行結果ではない。

画面切替、入力、表示用のページ切替等は動作する。経路探索、結線・点の配置、表示の移動・拡大縮小、音、実際の保存・読み込み・ファイル書き出し、チュートリアル用の実験は未実装。再試行等は入口の表示だけで、成功を検証したものではない。26機能の範囲は維持し、本体の設計・検証へ引き継ぐ。

## ブラウザで確認したこと

PC上のChromium・WebKitで**表示確認214件**と、各エンジンの見本による操作確認を完了。結果は[生成されたレポート](../../設計検証/操作画面/screen-layout-report-v0.1.0.json)。実機の実績ではない。

- 基本は320×480、360×640、390×664、430×780、480×240、568×260、844×310、768×1024、1280×800の9サイズ×11状態×2エンジン＝198件。
- 長い保存名、詳細のページ表示、0件の一覧、誤入力、回転、キーボードで使える高さが減った見本等を追加16件。
- ページ全体と操作欄内にスクロールがなく、内容を隠す `overflow:hidden` / `clip` を使っていないこと。
- ボタン文字のはみ出し、画面外の操作、見本の一覧が空表示になる失敗を検出すること。
- 40件の記録、10枠、詳細6項目をすべて辿れること。設定を経由しても記録のページ位置を保持すること。
- 時間と名前の全選択、誤入力の保持、回転後の入力保持、取消からの復帰。
- 一回の選択では通常画面のまま、PCのダブルクリックではポップアップを開くこと。開閉で実験エリアの大きさが変わらないこと。
- 記録や案内を開くときの見本の一時停止、閉じても自動再開しないこと。実行・一時停止中の設定変更入口を無効にすること。

最初の検証で詳細や短い横画面の保存失敗表示に内部のはみ出しを検出した。詳細をページに分け、余白とボタン幅を調整した。最終状態で再確認済み。

再実行例：

```powershell
node '設計検証/check_screen_layout.cjs' --playwright-path 'C:\Users\user\Documents\あとキュー\node_modules\.pnpm\playwright-core@1.62.1\node_modules\playwright-core' --browser-cache 'C:\Users\user\AppData\Local\ms-playwright'
```

既存のPlaywrightとブラウザを使用し、他のプロジェクトのソースは変更しない。一度に一つのエンジン・ページを使い、配信とブラウザは終了時に閉じる。

## 残る確認

短い横画面では図の名称・値と操作ボタンが小さい。表示が収まったことを、読みやすさ・指での結線・実機の合格とみなさない。実際の拡大縮小と操作領域の設計、文字拡大、端末のキーボードと安全な表示領域、タップ・長押し・二本指の操作、スクリーンリーダー、対象OS・ブラウザでの確認を残す。技術的な難しさで範囲を外さない。

課題モード、複数ゴール、故障全ケース、長い実行記録、名前・ファイルの不正入力と互換性、実際の保存失敗・再試行、案内履歴、PWAの更新・オフラインと本体の状態復帰は、後続の画面・処理・データ・試験設計へ対応付ける。今回の画面案を、それらの実装や確認完了へ置き換えない。
