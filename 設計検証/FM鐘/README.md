# FM鐘の調整版

後続の0.38.0では発案者がチャイムを選択し、短いエレピ打音を重ねて採用した。以下の3音は選択前の比較資料として保持する。再生成時の重なり検査は、現在の楽器音色のジングルを使用する。

試聴版 `2026.10.16-1`。発案者の「鐘の音を現状に合わせて調整」に対応し、採用前の3種類を現行の長さと音量へ合わせた。

Koekitの `two-op-bell-20261014` v2026.10.14-2を元にした2オペレーターFM合成。元の基準周波数（small 880Hz、chime 440Hz、large 約146.83Hz）・周波数比1対√2・最初と最後の変調の深さを保った。原本は変更していない。

## 調整

- 発音の上限は現行と同じ2.62秒。2.54秒から静かな最終フェードを行い、2.6秒で振幅0にする。途中の大きな音を切る方法ではない。
- 最大振幅を元の0.24から現行基準の0.2へ調整。試聴WAVは現行と同じコンプレッサー（大きな音を抑える処理）と共通音量70%を通す。端末の音量や人が感じる大きさの一致を保証する値ではない。
- 最初の0.6秒は3種類ごとの響きを残す。その後は音量の減衰を速め、1.5秒後の未達成音が埋もれにくくする。変調の減衰も短い音に合わせる。結果の音高・音数・開始時刻は変えない。
- 発音はサイン波2つだけ。録音サンプル・残響・追加の発振器を重ねない。WAVはこの処理の試聴用書き出しで、アプリへの取り込み用の発音処理は `fm-bells.js` にある。

WAVは48kHz・16bit・モノラルで、末尾の無音を含め3秒。`index.html` で比較でき、別の音を再生すると前の音を止める。各ファイルは `small.wav`、`chime.wav`、`large.wav`。

## 再生成と点検

プロジェクトのルートから、既存Playwrightを指定して実行する。

```powershell
node --max-old-space-size=512 設計検証/check_fm_bell_adjustment.cjs --playwright-path C:/Users/user/Documents/あとキュー/node_modules/.pnpm/playwright-core@1.62.1/node_modules/playwright-core
```

実際のPC ChromeのWeb Audioで音声を生成し、長さ・有限値・音量・減衰・停止・1個と3個同時の鐘＋既存未達成音を確認する。初回調整では3個同時の余韻が大きく、未達成音との信号差が不足して失敗した。後半の減衰を速め、同じ基準を通過させた。単なる音量増加や待機時間の延長には置き換えていない。

検査の結果は `report.json`。ここでの合格は音声信号とPCブラウザ操作の確認で、音色の好み・聞き分けの主観評価・Android/iPhone/macOS/iPad等の実機確認ではない。採用音の選択とアプリへの差し替えは未完了。現行アプリの表示版・配信資材・保存・記録・計算・ジングルは変更していない。
