## 0.50.0実装追補：演出の選択

演出の選択だけを専用のlocalStorageキー `prism-notes.motion.v1` に `{"version":1,"value":"auto"}` の形で保存する。valueはauto（初期値・端末に従う）、full（通常）、reduce（控えめ）。選択時だけ書き込み、ゲームの成績・回路・案内履歴・実行記録や書出しファイルへ混ぜない。

端末が伝える値とこの選択から表示用の実効値を決める。端末や別タブでの変更も反映する。未設定・読込不可・未知の版は元データを保持してautoへ戻り、保存に失敗した変更は適用せず元の選択を保つ。Windowsやブラウザそのものの設定を書き換えない。

詳細と検証は[演出設定](reviews/2026-10-17-motion-preference.md)を参照。

## 1. 主要データ

異なる用途の保存を混ぜると、回路の読み込みで実行状態や成績を上書きしてしまう。そのため次の単位を分ける。

| データID | 内容 | 保持・更新 |
|---|---|---|
| D-01 回路 | 点の識別子・役割・盤面座標・処理時間、道の識別子・両端・方向・移動時間、使用不可状態、実験方式・宛先 | 編集対象は一つ。自由の明示保存・回路ファイルの対象 |
| D-02 課題 | 課題識別子・版、候補の点と道、時間条件（お試し固定・実践抽選）・本数制限、評価種別・対象（複数祭壇は対象ID一覧）・間隔・回数、舞台、検証済み基準値、全粒終了までの検証済み最大時間 | アプリ資材として保持。お試し6課題と実践6課題すべて選択可能 |
| D-03 実行状態 | 固定した実験条件、時計、各粒の識別子・親子関係・宛先・直前の道・移動、各点の待ち列・処理中、実行／一時停止／停止の状態 | アプリ内のみ。一時停止・次動作で保持。再実行は新しく作る |
| D-04 実行記録 | 実行識別子・条件、粒ごとの通過・到着・処理開始／終了・終了理由、到着回数 | 現在の実験に結び付ける。結果ファイルへ明示書き出し |
| D-05 評価 | 課題と規則の版、故障ケースごとの条件・到達結果、判定状態、到達時間・本数・初回時間・真の点数 | 未確定と未達成を分ける。見た目の丸め前の値で比較 |
| D-06 回路保存枠 | 最大10枠。枠識別子・名前・形式版とD-01 | localStorage。任意保存・ユーザーが選ぶ置換・名前変更・確認後削除 |
| D-07 成績 | 課題・出題と採点規則の版、達成状況・最高点と比較に必要な値、実際の出題条件 | 端末内に達成時の自動保存。低い点・未達成で以前の最高点を消さない |
| D-08 案内履歴 | 課題／自由ごとの完了・スキップ | 端末内。開始だけで完了扱いにしない |
| D-09 案内用の一時保持 | 元の回路・条件・実行状態・結果・表示位置等 | アプリを開いている間のみ。練習後に元へ戻す。10枠は使わない |
| D-10 アプリ資材 | コード、課題・見本、ロゴ・画像・フォント・音等、資材版と準備状態 | PWA用の資材保持。回路保存と別 |

## 2. 時間・識別と関連【想定】

- 道を識別子で区別し、同じ二点の複数道と直前の道を正しく扱う。名前変更で保存対象を取り違えない。
- 回路から実行条件の写しを作り、実行記録・結果はその条件へ関連付ける。編集後の回路と古い結果を同じ条件として表示しない。
- 有限小数の時間を正確に扱う共通単位へ変換し、整数等で計算する。JSONへ書き出す方法と精度・扱える範囲はT-02・06で定義する。自由の0.1秒刻みと読み込んだ適正な既存値を勝手に丸めない。
- 実験の経過秒は暦の日時と別。保存日時を追加する場合だけUTCのISO 8601形式で保持し、端末のタイムゾーンで表示、不明ならAsia/Tokyoを使う。日時入力の機能は加えない。

## 3. 保存とファイルの境界

| 対象 | 含める | 含めない |
|---|---|---|
| 自由の10枠・回路ファイル | 回路の構成・条件、名前・識別・形式版 | 実行中の粒、待ち列、実行記録、課題成績 |
| 結果ファイル | 実行に使った条件・実行記録、判定結果との対応 | 途中実行を再開できるという保証 |
| 成績 | 達成状況・最高点・比較に必要な課題／出題／規則の版と実際の出題条件 | 回答回路や全実行履歴の自動保存 |

ファイルは用途・形式版を識別するJSONを候補とする【想定】。読込対象は回路ファイル。結果ファイルのアプリ内読込・比較機能は追加せず、外部で条件と記録を確認できる形にする。未対応版や不正な参照・時間・役割は検査し、現在の編集内容を変えず知らせる。具体的な互換性・項目・入力可能範囲は実装時に定義する。

## 4. 失敗と更新

保存は候補を作り、旧内容を先に消さず更新する【想定】。失敗なら編集内容・入力名・以前の保存内容を保持。「保存して入替」の保存失敗では入替しない。成績の未保存候補と保存済み最高点は分け、結果欄から再試行できるようにする。終了後の未保存候補の復元保証は加えない。

削除は確認した一枠のみ。名前変更は構成を変えない。保存内容・ファイル名をHTMLとして実行しない。形式更新で既存データを無断削除せず、読める旧形式は非破壊で読み、変換失敗時は元データを保持する【想定】。採点版が異なる値をそのまま比較しない。

詳しい保護と回復は[保存と読み込み案v0.2](../基本設計_保存と読み込み案_プリズム・ノーツ.md)。記録量・保存容量・性能の限界は実測対象で、無限保持を保証せず、勝手な削除や粒の統合で対処しない。
