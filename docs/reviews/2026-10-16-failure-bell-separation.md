# 鐘の余韻と未達成音の間隔

2026-10-16 / 0.36.0。実装・公開済み。追加の表示・操作修正を含めた最終の公開確認は、後続0.37.0の点検にまとめる。

## 理由と変更

発案者の「鐘の音に未達成音が埋もれている可能性」の指摘と、間隔を調整する指示を対象とする。0.35.0では鐘の音が約2.62秒続く一方、未達成音は終了0.42秒後から入っていた。Q6で星→A→鐘の1経路だけを結ぶと、最後の鐘への到達と未達成の確定が同じ更新で起こり、両方の音が重なることを確認した。以前の「鐘が鳴らない未達成」での発音確認だけでは、この重なりを検査できていなかった。

未達成の下降2音は、終了0.42秒後と「最後の鐘から1.5秒後」の遅い方から鳴らす。鐘が鳴っていない場合や、すでに十分前に鐘が鳴っている場合には、不要な追加待機を入れない。鐘の余韻は自然に残し、その音程・音量・長さを変えない。通常クリアの従来4音、満点の8音と和音、未達成の音程・音量も保つ。

最後の鐘と終了が同時でも、未達成の2音は終了から約2.08秒以内で鳴り終わり、従来どおり3秒で編集へ戻る。待機を到達時刻・実行時計・採点・全記録へ加えない。停止・消音・メニュー・記録などによる音の取消、結果ごとに一度だけ鳴る条件、自由・案内・途中中断の除外も保持する。

設定は `src/ui/audio.js` の `FAILURE_BELL_DELAY_SECONDS=1.5`。鐘の最後の発音時刻を既存の余韻管理から求め、未達成の2音だけに同じ長さの待機を加える。音量の上乗せや鐘の強制打ち切りはしない。

## 検証

- 音の単独テストへ、同時の鐘・続けて鳴った最後の鐘の両方で1.5秒空くことと、3秒内の完了を追加した。修正前は5.42秒に発音するため、期待6.5秒との比較で失敗し、修正後は合格した。既存の結果選択と合わせ18件合格。
- `設計検証/check_outcome_audio.cjs` に、実際のQ6で鐘と未達成を発生させる操作を追加。発音予約だけで終わらず、2音の自然な終了まで画面を操作せず待ち、実時間の混合音の信号と3秒での自動編集復帰を検査する。
- `npm.cmd test`：17ファイルを最大5ファイルずつ、並列度1で実行し140件合格。到達時刻・全記録・保存、全48出題の全配線と既存の終了待機も含む。
- `npm.cmd run check`：51ファイルの構文検査が合格。`npm.cmd run build`：0.36.0の42資材を生成。
- PC Chromium／WebKitの結果音検査は19件合格。ChromiumのQ6では最後の鐘から1.5秒後に1音目が始まり、終了後約2.067秒で2音とも自然に終了した。同じ測定地点で、開始直前の鐘だけの信号は最大約0.00867、未達成音が入った信号は約0.09384。測定は共通音量の手前の音声処理経路であり、端末の音量や聴感の測定ではない。Windows用WebKitは音声APIがなく、結果・記録と自動編集復帰を確認し、発音・聴感を未確認として残した。
- インストール済みWindows Chrome／Edgeも専用の検証状態で各10件合格。両方でQ6の実時間の混合信号、1.5秒の間隔、2音の自然な終了と自動編集復帰、停止・消音と再表示時の重複防止を確認した。

最終の公開点検は後続の0.37.0で実施し、[点検記録](2026-10-16-bell-visibility-wire-selection.md)へまとめた。音声信号の大きさを、人が聞き分けられたことと同じには扱わない。Android Chrome／iPhone Safariの聴感、Windows実スピーカー、macOS／iPadを含む全対象の未確認事項は保持する。
