# 秒数を変える実践課題の実装

2026-10-16 / 0.33.0。実装・公開済み。公開と確認結果は末尾を参照。

## 変更と保存の扱い

発案者の実装指示と後続の選択に従い、Q1～Q6を固定のまま、Q7～Q12で道の秒数を抽選する。元の数値の並べ替えに加えて数値自体も調整する。候補・本数制限・プリズムの処理時間・課題の目的を維持する。

各課題8種類、合計48種類の秒数条件を用意した。事前に本数制限内の全配線を計算するため、端末では検査済みの数値を選ぶだけで済む。各出題は満点配線が1通り、かつ別の配線で部分点クリアできる。余分な線を加えた配線も別に数える。満点基準と動作上限は出題ごとに検証した値を使い、採点式は維持する。

課題を新しく選ぶ時、同じ課題を選び直す時、次の実践課題へ進む時に抽選し、直前と同じ出題は避ける。「もう一度」・配線クリア・停止再開・メニューや記録・案内の往復では同じ秒数を保持する。自由の未保存回路からの入替を取消した時や、入替候補の事前検査だけでは抽選を消費しない。専用の再抽選ボタンは増やさない。

画面には「出題1」などを控え目に表示する。成績は固定版と各出題で識別情報を分け、元の秒数・目的・満点基準・動作上限を保存する。課題一覧は固定版と各出題の成績を集計した「最高点（全出題）」を表示する。実行記録の書き出しにも、実行開始時の完全な課題条件を加える。保存形式の版を変えず、旧成績・自由の保存枠・案内履歴・停止後の全記録を保持する。保存失敗で別出題へ進んでも、各元条件で再保存できる。再保存候補の課題名・出題番号・点数は既存の折り返す行で表示し、末尾を省略しない。

## 作問と検証

生成は `npm.cmd run generate:challenges`。生成器は候補秒数の相対差を変える提案と、点ごとの時間差を道へ割り当てる提案を検査し、すべての許可配線を実行処理で最後まで計算する。各課題で240回までの生成、現在の全列挙検証器は16候補まで、1配線2048ステップまでを明示的な資源上限とする。上限内で確認できなければ生成を失敗させ、未検証の問題を出さない。これをゲームのプリズム数・自由作成や将来の課題追加の上限にはしない。

満点の唯一性と部分点だけでなく、クリアするすべての配線にプリズムの分岐があり、Q9・Q10は複数の分岐点、Q11・Q12は実際の合流待ちがあることを検査する。局所的には短く見える不正解の候補も残し、最短の秒数だけを選ぶ方法へ偏らせない。条件を成立させるために、道や点を削除しない。候補値は正確な0.1秒単位で計算する。

48出題で合計299,280の配線構成を検査。Q8～Q12ではそれぞれ2通りの異なる満点配線を含めた。Q7の8出題は数値が異なるが、満点配線は共通。「48種類の秒数条件」であり、「48通りの異なる解法」「選び直すと必ず正解配線も変わる」とは説明しない。試行錯誤の面白さ・体感難易度を自動検査だけで合格にしない。

配信するのは識別情報・秒数・基準・上限を持つ出題データ。正解配線や検証用の部分点配線は設計検証/ランダム課題/generation.jsonに置き、アプリの配信資材へ含めない。再生成の結果はこの証拠とsrc/content/random-variants.jsを組として保存する。

自動テストは公開のSession操作・LocalRecords・全配線のSimulationを使う。再抽選と保持、取消、案内復帰、固定版との成績分離、条件の書き出し、成績未保存の再試行を確認する。旧固定版の数値を使う従来の二つの操作テストは、旧固定条件を明示した合成入力として維持する。ランダム版の試行を旧4秒等へ無理に合わせない。

ブラウザの検証器は設計検証/check_random_challenges.cjs。Chromiumは「次の動き」、WebKitは通常の連続再生を使う。初めと終わりの出題を再現可能な抽選で選び、画面で結線・満点・再編集・クリア・再選択・部分点・次課題を操作し、実際の書き出しファイルと保存条件を照合する。既存のcheck_advanced_challenges.cjsとcheck_offline_features.cjsも表示中の出題に合う検証用配線を使う。

途中の検証では、秒数表示の要素を探す名称の誤りによる空配列、直通線のドラッグが途中のプリズムを通ることで連続結線になるケースがあった。前者は実際のedge-timeを読むよう修正し、後者は個別の直通線の検証に限って途中の点を避ける操作とした。アプリの連続結線仕様を変えた解消ではない。WebKitでは同期的に次動作を高速連打した合成操作で負荷保護が働き、達成結果を保ったまま通知が抑制される途中不合格も確認した。描画と操作間隔を区切って通常の操作を再検証し、負荷保護を解除した合格にしない。途中不合格と最終結果を分ける。

表示の点検では、WebKitの通常再生でも負荷保護による一時停止が出た。途中の測定は計算6ms・表示206msなどで、表示側の時間が大きかった。到着演出の同じ要素を再利用し、星座の位置測定をまとめ、星座がない時の配置処理を省く。秒数カードの同じ候補の重なりを1ラベルの検討中だけ再利用し、変更のない状態文字・ボタン文字・配線数欄を作り直さない。見た目・演出時間・負荷保護の閾値・時計・全記録は変更しない。個別のQ10再検査では満点と部分点が最後まで通過した。最終結果は下段へ記録する。旧0.32.0の実ソースから作った比較環境ではQ7・Q10が正常終了しており、途中不合格を単に旧版にもある問題と断定しない。

文字拡大の実画面検査では、WebKitのQ12でFGの秒数カードとプリズム名Cが重なる途中不合格があった。通常・拡張の格子候補だけでは盤面端の細い空きが拾えないため、その場合に限り四辺と障害物の境界に沿う候補を追加した。文字サイズ・カード数・候補の道は減らさず、文字拡大を対象から外さない。最初のlayout-only検査は、Sessionの生成後に乱数関数を置き換えていたため、8出題を一巡した保証がなかった。設定を起動前へ移し、各回の実際の識別情報と期待する8件を照合してやり直した。修正後の40点検は両エンジンで合格し、Q12の全8出題をCSS28pxで確認した。

成績再保存の追加検査では、画面下の「成績再試行」が一覧を開くという検査側の取り違えがあった。このボタンは直接再保存する既存動作で、変更しない。メニューの「成績未保存を再試行」から一覧を開き、表示中であることとQ12の出題番号を確認してから寸法・再保存を検査するよう修正した。隠れた旧ダイアログのゼロ寸法を全文表示の合格にしない。

仕様レビューは必須修正0件、作業指示・保守のレビューも必須修正0件。保守上の指摘を受け、成績の識別情報の生成・保存照合・一覧集計をsrc/core/challenge-identity.jsへ集約した。再確認でも必須修正の指摘なし。
