# ストーリーの本体組み込み

発案者が独立試作0.1.9を確認し、「26・27で琴が動くのを修正」「音はゲーム設定を引き継ぐことを確認」「本体へ組み込み」を依頼した。今回の本体版は0.104.0。コミット・公開まで今回の許可に含め、既存差分を保持して進める。

## 実装

- 承認済み27枚を `src/content/story.js` へ、絵・音の閲覧を `src/ui/story-reader.js`・`story.css`・`story-voice.js` へ移した。必要なROOT採用素材14枚を `public/story/` に追加。語りと音の内容は試作を保持する。
- 26・27枚目は同じ静止WebPの琴を使っていたが、配置と大きさが違っていた。26枚目にそろえ、ハンマーも同じ位置に保つ。琴への個別の動き・変形も無効にする。
- 本体のChimeを共有し、消音中は物語を開いても解除しない。音の有効化は明示操作だけ。70%の共通音量とゲームの出力遅れ設定をそのまま使う。演出の控えめ設定も本体と共有する。
- 連続プレイの最初、4・6・7・13・19・25・31・37面の前、全42面を順にクリアした後に対応する物語を挟む。選択プレイや物語の再閲覧を全面クリアにしない。100点や全288出題の達成を追加条件にしない。
- クリアの「次へ」を押す導線を保ち、境目では残っている鐘・結果音の余韻を待つ。公式時計・採点・実行記録は触らず、停止・消音・別画面・新しい実行・非表示は進行予約を取り消す。
- 読み終えた後に、従来の初出説明と面の開始演出へ進む。物語のスキップをゲームのクリアに混ぜない。
- タイトルとメニューの「おはなし」から27枚を読み返せる。通常のプレイ中の成績・回路を変えない。曲は予約場面のみ。
- 物語途中の「タイトルへ」から「続き」で同じページへ戻れる。進行は従来の連続プレイと同じくこのページの中で管理する。再読み込み後の新しい自動再開や既読の永続保存は追加せず、既存の成績・保存回路を保持する。

## 保持と検証

作業前のHEADと追跡ファイルのハッシュ、既存差分一覧は `design-preview/story-integration-2026-11-19/evidence/baseline.json` と `baseline-status.txt` に保存。既存の設計検証画像・報告をコミットへ混ぜない。

42面の実IDを使った境界・全面クリア・二重通知・取消の単体5件が合格。Chrome・WebKitの通しプレイは各42面を実際の結線操作と実時間でクリアし、10ブロックを順に経て結末まで合格。時計の差し替えやSessionの状態設定は使わず、最初の出題と既存の正解配線を操作した。結果カードの保存設定を0秒にして、Chromeでは鐘の余韻が残る境目で待機・停止・押し直しを検査した。時計・到達時間を保持し、両ブラウザとも負荷停止とブラウザエラーは0件。

表示はChrome 221項目・WebKit 220項目が合格。全27枚×8寸法（320×480、360×640、410×844、844×410、740×280、568×260、480×240、1440×900）で画面内の配置、操作の当たり、本文の横欠け、全文スクロール、少なくとも本文1行分の高さを確認。琴は通常の演出で4寸法の時間経過と26→27の矩形・変形・動きを比較し、すべて一致。タイトルは既存の小画面用34〜38px以上のボタン寸法を保ち、物語内のボタンは44px以上で検査した。

Chromeではゲームと物語で音声出力が1つ、保存された出力遅れ0.07秒が共通、双方からの消音が共通であること、9と8の鐘の同時刻、6つの精霊の発声ノード、停止後の古い予約の取消を確認。WebKitの今回のWindows環境には音声APIがないため、表示・進行の証拠と発音の証拠を区別する。

通常導線は両ブラウザ各10ケースが合格。タイトル7寸法、物語の中断→再閲覧→続き、章のスキップ、選択プレイの42面を実際にクリアしてもエンディングを得ず一覧へ戻ること、自由・チュートリアルに物語が自動で入らないことを確認した。

更新は実際に公開した0.103.0（71c734b）のソースから旧配信を再現し、両ブラウザ各3ケースが合格。旧版で実際に1面をクリアした成績1件、保存回路1件、別タブの未保存配線2本を用意し、更新後も保存内容の全バイトと別タブの回路を保持した。HTTPキャッシュを使わない配信元を停止し、Chromeは通常キャッシュも消して通信を遮断した後、新しいタブからWorker経由で0.104.0を再起動。物語を初めて開き、27枚の画像の復号・全文・曲の予約場面・物語用フォントを確認。WebKitは配信元停止を通信断の根拠とし、音声API未搭載を発音の合格へ含めない。

Chromeの更新検査では、待機中のWorker（通信なしのための処理）へ自動操作側から接続しない条件で、切替待ちが時間切れになった。WorkerのVERSIONと資材数を読取専用で確認してから、診断による関数差し替えなしで同じ更新ボタンを押すと、旧版更新とオフライン27枚が合格した。内部原因は未確定で、実機でも更新に失敗すると断定しない。更新コードを変える仮説は改善せず、変更と仮説用テストを取り除いて元のコードを保持した。初回失敗と診断結果はevidence内のPWAレポートに残す。WebKitはこのWorker検査を挟まず更新できた。

検査途中で見つけた不具合も記録した。既存PC用ダイアログの大きさ指定が物語にもかかり640×640に縮んだため、物語だけを対象外にした。境目のタイマーをオブジェクトのメソッドとして呼ぶとブラウザで `Illegal invocation` となり、余韻待ちと取消が失敗したため、通常の関数呼び出しで包む形へ修正。停止時は待機だけを取り消し、確定済みの結果を再評価しない。修正後の通し操作で待機取消と進行を確認済み。

検査側も、非同期条件の完了を待てない `waitForFunction(async …)` を既存の `waitForAsync` にそろえて再実行した。初回の得点表記の仮定（100点／実際は100.00点）と、タイトルへ物語の44px基準を一律に課した仮定は検査側を訂正し、ゲームの元の表記・寸法は変えなかった。製品不具合の失敗記録と再実行の結果は今回専用のevidence内に残す。

追跡ファイル4,037件を着手時と比較し、今回の明示した対象以外の変更は0件。ROOT素材14点は、ROOT原本・確認済み試作・本体コピーでSHA-256が一致する。既存の未追跡資料・試作・設計検証結果はそのまま保持し、今回のコミットに混ぜない。
