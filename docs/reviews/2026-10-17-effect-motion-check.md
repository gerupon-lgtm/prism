# PCとスマホ相当画面の演出点検

2026-10-17 / 確認対象は公開版0.45.0。アプリの動作や端末設定の変更は行わず、演出の設定分岐を確認する。

## 報告と通常のChromeで確認したこと

発案者から「PCでクリアすると花火が一度に表示される。スマホはアニメーションに見える。他の演出も確認してほしい」と報告があった。

このPCの普段使いのChromeで、ゲームのタイトル画面を開いて読み取った結果は次のとおり。課題の実行や成績の変更は行っていない。

- 表示版：0.45.0。
- `prefers-reduced-motion: reduce`：true。
- `prefers-reduced-motion: no-preference`：false。

この条件では、アプリが端末側から受け取る「動きを減らす」が有効。花火5発を静止表示し、打ち上げの線を隠す既存の仕様に一致する。スマホ実機の設定は今回読み取っていないため、その設定値までは補わない。

同じPCでも、画面を表示しない検証用Chrome／Edgeの既定値はreduceがfalseだった。自動検証用ブラウザの既定値を、利用者の通常ブラウザが受け取る設定の証拠にしない。

## 検査方法

`設計検証/check_effect_motion.cjs` でQ1を実際の操作から配線・実行し、自然に進む画面を約65msごとに採取する。アニメーションを一時停止したり、再生位置を指定したりしない。

PC画面1366×900とスマホ相当390×844それぞれで、通常／動きを減らすを明示して比較する。静止表示の確認は端末設定の模擬であり、Windowsや利用者のブラウザの設定そのものを書き換えない。経路の粒、開始前の短い演出、プリズムの光片と光、鐘の光柱・光芒、星座の星と線、花火、消去後の編集復帰を検査する。

| 対象 | 通常 | 動きを減らす |
|---|---|---|
| 花火 | 5発が180msずつずれ、打ち上げ・光の線が進む | 5発を同時に静止表示。打ち上げ線は非表示 |
| プリズム | 光片が広がり、光が変化する | 光片と光を静止表示 |
| 鐘・星座 | 光柱・光芒が変化し、星が現れて線が伸びる | 完成した星座と光を静止表示 |
| 光の粒 | 経路を移動する | 経路を確認する本体の動きとして維持 |
| 開始・終了 | 短い開始準備後に実行し、達成後は編集へ復帰 | 同じ実行・復帰を維持 |

## 結果

Windows ChromeとEdgeは各4条件に合格した。通常時に花火がすべて一度に出る現象は再現せず、時間差を持って表示された。reduceでは5発の出現時刻が同時だった。

公開版のEdgeで、花火開始から約150msと約950msの画像も保存した。通常時は打ち上げ・開花の段階と星座のつながりが変わり、reduceの2画像はSHA-256が一致した。画像は `設計検証/演出の動き/msedge/`。

復帰の検査は、サンプリング開始からの固定時間を実行開始時刻と混同しないよう、実際の編集状態まで待つ。WebKitでの最初の検査はこの早すぎる状態確認で失敗し、自然な演出の検査と分けて保持した。

公開版Chromium・WebKitも8条件に合格し、Windows Chrome／Edgeの各4条件と合わせて16条件に合格した。アプリの演出コードと配信資材は変更せず、公開版・資材版は0.45.0のまま保持する。記録は `設計検証/演出の動き/`。

今回の範囲はPC上の実時間表示と、利用者の通常Chromeが受け取る設定の読み取り。スマホ実機・macOS Safari・iPadの今回の再確認は未実施で、対象から外さない。合成した表示条件を実機の見え方や描画性能の合格に広げない。
